# The actual fix - inline thumbnails as data URIs

2026-04-20 ~15:52 PT. Original: `git show b012073:investigation/1776726600_07_actual_fix.md`.

## The real problem
MCP Apps works in Claude Desktop chat. Kai's test showed the iframe and card grid
rendering, and the RPC log showed `tools/list` with `_meta.ui.resourceUri`, then
`resources/read ui://app/preview.html` returning 308KB of HTML.

The one bug: external thumbnail URLs are blocked by the iframe's hardcoded
`img-src 'self' data: blob: https://assets.claude.ai` CSP. This is
[anthropics/claude-ai-mcp#40](https://github.com/anthropics/claude-ai-mcp/issues/40):
claude.ai ignores `_meta.ui.csp.resourceDomains`. @antonpk1 (2026-04-09) said nested
iframes cannot be allowed for security reasons, and the hardcoding covers `img-src`.

## The workaround
`data:` URIs are always allowed, so fetch thumbnails server-side and inline them as
`data:image/jpeg;base64,...` before building the payload. Patch to `server.ts`:

- `inlineThumbnail(url)` fetches with an access token, 2.5s timeout, 500KB cap, and
  returns a `data:` URI or null.
- `inlineThumbnails(projects)` fans out with `Promise.all`.
- `list_items` inlines the limited set, `open_item` inlines the one project.

The smoke test gave data URIs of 17,999 to 34,279 chars. Payload overhead is ~200KB for
8 projects, against a 308KB bundle. The React code already passes `thumbnailUrl` into
`<img src>`, so no UI rebuild was needed, only `npm run build:node`. MCPs load at
startup, so Kai had to `Cmd+Q` Claude Desktop, reopen, and ask for her recent items.

## Revised conclusions
- MCP Apps works in Claude Desktop chat today.
- CCD genuinely lacks it (`local-agent-mode-*` does not advertise the UI extension).
- The `claudemcpcontent.com` sandbox CSP (#40) binds every MCP app: use data URIs for
  images and fonts, and inline scripts.
